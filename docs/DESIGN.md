# 슬롯 유닛 배틀 게임 개발 설계서

2026-11-21 기준

## 1. 개요

슬롯을 돌려 나온 그림 조합대로 유닛이 소환되고, 유닛이 자동으로 전진해 적 성을 부수는 3분짜리 1인용 전투 게임입니다. 가칭은 "슬롯 배틀"입니다.

이 문서는 Claude Code에 그대로 넘겨 개발을 요청하기 위한 설계서입니다. 수치는 모두 초기값이며 플레이하면서 조정합니다.

**목표**

- 1차 목표는 "한 판이 재미있는가"를 검증하는 것입니다.
- 1차 버전은 서버 없이 무료로 출시합니다.
- 유료화와 대전 기능은 나중에 붙이되, 구조는 처음부터 그 확장을 전제로 잡습니다.

**1차 출시에 넣는 것**

- AI 상대 스테이지 10개
- 유닛 8종(전체 설계 15종)과 덱 5종 편성, 슬롯 3칸, 고정 후 다시 돌리기, 직접 배치
- 판 중간에 고르는 강화 카드
- 유닛 육성: 골드 레벨업, 조각 승급, 고유 기술 해금
- 기기 내 저장, 보상형 광고

**1차 출시에서 빼는 것**

- 실시간 대전, 로그인, 서버
- 유료 뽑기와 현금 결제 상점(구조만 준비)
- 길드, 채팅, 랭킹

**차별화 원칙**

기존 게임의 장르와 규칙 아이디어만 참고합니다. 캐릭터, 그림, 화면 구성, 이름, 수치표는 모두 새로 만듭니다.

**세계관: AI 로봇 전투**

플레이어는 로봇 공장을 지휘하는 AI 사령관입니다. 슬롯은 로봇을 찍어내는 무작위 조립 라인이고, 같은 부품이 맞을수록 상위 기종이 조립되어 적 AI의 기지를 공격합니다.

| 이 문서의 규칙 용어 | 게임 화면에 보이는 이름 |
| --- | --- |
| 성 | 코어 기지 |
| 마나 | 에너지 |
| 슬롯 | 조립 라인 |
| 유닛 1·2·3단계 | 기본형, 강화형, 합체형 |
| 강화 카드 | 전술 모듈 |
| 골드, 보석, 조각 | 크레딧, 코어 칩, 부품 |
| 레벨업, 승급(별 1~5) | 업그레이드, 기종 개량(Mk.1~Mk.5) |

- 로봇은 단순한 도형을 조합한 귀엽고 뚜렷한 실루엣으로 직접 디자인합니다. 기존 로봇 작품이나 게임의 디자인을 닮지 않게 합니다.
- 연출도 세계관에 맞춥니다. 타격은 불꽃과 금속음, 파괴는 부품이 흩어지는 폭발, 소환은 조립되며 투하되는 장면, 합체형은 합체 연출로 표현합니다.

## 2. 게임 규칙

한 판은 마나로 슬롯을 돌려 유닛을 소환하고, 3분 안에 적 성을 먼저 부수면 이깁니다.

**화면 구성(세로 화면)**

- 위쪽에 적 성, 아래쪽에 내 성, 가운데에 좌우 2개의 전투 라인이 있습니다.
- 화면 맨 아래에 3칸 슬롯, 마나 게이지, 돌리기 버튼이 있습니다.

**한 판의 흐름**

1. 마나가 초당 1씩 차오릅니다(최대 10, 시작 5).
2. 마나 3을 써서 슬롯을 돌립니다.
3. 결과가 마음에 들면 확정합니다. 나온 유닛은 바로 싸우지 않고 대기 칸(최대 4기)에 들어갑니다. 대기 칸이 모자라면 확정할 수 없고, 유닛을 놓아 자리를 만든 뒤 확정합니다. 확정하기 전에는 다음 스핀을 할 수 없습니다.
4. 마음에 안 들면 한 칸을 고정하고 마나 1로 나머지 두 칸을 다시 돌립니다(한 번의 스핀당 1회). 반드시 한 칸을 고정해야 하며, 고정 없이 세 칸을 모두 다시 돌릴 수는 없습니다.
5. 대기 칸의 유닛을 끌어다 내 진영의 원하는 라인과 위치에 놓습니다. 놓인 유닛은 자동으로 전진해 싸웁니다.
6. 60초와 120초에 강화 카드 3장 중 1장을 고릅니다(고르는 동안 전투는 멈춥니다).

**슬롯 소환 규칙**

| 결과 | 소환되는 유닛 |
| --- | --- |
| 세 칸이 모두 다름 | 각 그림의 1단계 유닛 1기씩, 총 3기 |
| 두 칸이 같음 | 같은 그림의 2단계 유닛 1기 + 나머지 그림의 1단계 유닛 1기 |
| 세 칸이 모두 같음 | 그 그림의 3단계 유닛 1기(잭팟 연출) |

**전투 규칙**

- 유닛은 놓인 라인을 따라 적 성을 향해 직진합니다. 다른 라인의 적은 공격하지 않습니다.
- 사거리 안에 적 유닛이 있으면 가장 가까운 적을 공격합니다.
- 적 유닛이 없고 성이 사거리 안이면 성을 공격합니다.
- 배치한 뒤의 유닛은 직접 조종하지 않습니다. 실력은 무엇을 언제 어디에 놓느냐에서 갈립니다.
- 적은 슬롯을 쓰지 않고, 스테이지별로 정해진 시간표대로 유닛을 내보냅니다.

**승패**

- 적 성의 체력이 0이 되면 승리, 내 성이 0이 되면 패배입니다.
- 3분이 지나면 성 체력 비율이 높은 쪽이 이깁니다.
- 마지막 30초는 마나 회복이 2배입니다.
- 승리하면 골드를 받고 다음 스테이지가 열립니다. 남은 성 체력에 따라 별 1~3개를 줍니다.

**실력 요소: 배치와 타이밍**

운은 "무엇이 나오느냐"까지만 정하고, 승패는 "어디에 언제 놓느냐"로 갈리게 합니다. 같은 슬롯 결과를 받아도 잘하는 사람이 이기는 게임이 목표입니다.

| 실력 요소 | 플레이어의 판단 | 규칙 |
| --- | --- | --- |
| 라인 선택 | 적이 몰려오는 라인을 막을지, 빈 라인으로 밀어붙일지 | 라인 2개. 유닛은 자기 라인의 적과만 싸움 |
| 배치 위치 | 성 앞에 놓아 방어할지, 중앙선 가까이 놓아 빨리 도달시킬지 | 내 진영(전장 아래 절반) 어디든 배치 가능 |
| 배치 순서 | 버티는 유닛을 앞에, 원거리 유닛을 뒤에 세우기 | 유닛마다 이동 속도가 달라 놓는 순서와 간격이 대형을 결정 |
| 타이밍 | 하나씩 내보낼지, 대기 칸에 모았다가 한꺼번에 밀지 | 대기 칸은 최대 4기. 가득 차면 스핀 불가 |
| 상성 대응 | 적 조합을 보고 유리한 유닛을 맞세우기 | 아래 상성표 |
| 에너지 관리 | 지금 돌릴지, 다시 돌릴지, 사령관 기술에 쓸지 | 스핀 3, 다시 돌리기 1, 사령관 기술 4 |
| 사령관 기술 | 적이 뭉친 순간을 노려 직접 조준 | EMP 폭격: 지정한 위치 반경 2.0 안의 적에게 피해 40, 2초 정지. 재사용 대기 30초 |

**상성표(초기 설계)**

| 유닛 | 강한 상대 | 약한 상대 |
| --- | --- | --- |
| 블레이드봇 | 슈터봇(붙으면 이김) | 실드봇 |
| 슈터봇 | 실드봇(느려서 오래 맞음) | 대시봇 |
| 실드봇 | 블레이드봇, 대시봇(돌파 차단) | 플라즈마봇 |
| 플라즈마봇 | 뭉쳐 있는 적 전체 | 대시봇, 블레이드봇 |
| 대시봇 | 슈터봇, 플라즈마봇(빠르게 접근) | 실드봇 |

**실력이 실제로 반영되는지 검증하는 방법**

- BalanceSim에 자동 플레이어를 두 종류 둡니다. 하나는 아무 라인에나 즉시 놓는 초보형, 다른 하나는 상성과 대형을 따져 놓는 숙련형입니다.
- 같은 시드(같은 슬롯 결과)로 두 플레이어를 돌렸을 때 숙련형의 승률이 25%포인트 이상 높아야 합니다. 차이가 작으면 운에만 좌우되는 게임이라는 뜻이므로 상성과 수치를 조정합니다.
- 이 검증은 M1의 완료 기준에 포함합니다.

적 AI도 스테이지별 시간표에 라인을 지정해 내보냅니다. 후반 스테이지는 한쪽 라인에 몰아 보내거나 양쪽을 번갈아 찌르는 패턴으로 대응 실력을 요구합니다.

**유닛 특성 규칙**

- 공중 유닛은 "공중 공격 가능"(대공) 특성이 있는 유닛에게만 공격받습니다. 공중 유닛 자신은 지상 유닛, 공중 유닛, 성을 모두 공격할 수 있습니다. 상대가 대공 유닛을 안 넣었을 때 특히 강합니다. 1차 출시 8종 중 대공은 슈터봇과 드론봇입니다.
- 특성은 유닛 데이터의 키워드(공중, 대공, 범위, 자폭, 치유, 설치, 공성, 생산, 방해)로 표현하고, Core는 키워드별 처리기를 둡니다. 새 유닛은 JSON에 키워드를 조합해 추가합니다.
- 등급이 높을수록 슬롯에 덜 나옵니다. 칸마다 나올 가중치는 일반 25, 희귀 18, 영웅 12이고, 덱에 넣은 5종의 가중치 합으로 나눠 확률을 정합니다.
- 1차 출시는 8종입니다. 블레이드봇, 슈터봇, 실드봇, 스웜봇, 플라즈마봇 5종을 가지고 시작하고, 붐봇·대시봇·드론봇은 스테이지 3·5·7 클리어 보상으로 얻습니다.
- 나머지 7종은 출시 후 업데이트로 추가합니다. 유닛이 늘수록 덱 5종을 고르는 것 자체가 전략이 됩니다.
- 거리 단위는 라인 길이를 20으로 놓은 값입니다. 이동 속도는 초당 거리입니다.
- 2단계 유닛은 체력과 공격력이 2.2배, 3단계는 5배입니다. 같은 그림을 맞추는 쪽이 항상 이득이 되도록 한 값입니다.
- 슬롯에는 덱에 넣은 5종의 그림만 나옵니다.
- 성 체력은 양쪽 모두 1,000에서 시작합니다. 스테이지가 적 성 체력을 따로 정하면 적 성만 그 값을 씁니다.

**강화 카드(판 안에서만 유효, 1차 12장)**

| 분류 | 카드 예시 |
| --- | --- |
| 유닛 강화(덱에 넣은 유닛별 1장씩, 5장) | 해당 유닛 체력·공격력 +25% |
| 슬롯 강화(4장) | 스핀 비용 -1, 다시 돌리기 무료, 특정 그림 가중치 2배, 고정 칸 2개 허용 |
| 자원·성(3장) | 마나 회복 +25%, 최대 마나 +3, 성 체력 300 회복 |

**스테이지**

- 스테이지마다 적 성 체력과 적 소환 시간표(몇 초에 어느 라인에 어떤 유닛 몇 단계)를 가집니다.
- 1~3은 규칙을 익히는 쉬운 단계, 4~7은 적 조합이 다양해지는 단계, 8~10은 영구 강화가 있어야 깨는 단계입니다.

**유닛 육성(판 밖 성장)**

유닛 육성이 판과 판을 잇는 장기 목표입니다. 한 판의 운은 슬롯이, 계정의 성장은 육성이 맡습니다.

| 육성 요소 | 재료 | 효과 | 한도 |
| --- | --- | --- | --- |
| 레벨업 | 골드 | 레벨당 체력·공격력 +8% | 별 등급 × 10레벨 |
| 승급(별 1~5) | 그 유닛의 조각 | 레벨 한도 상승, 외형 변화, 고유 기술 해금 | 별 5개 |
| 고유 기술 | 승급 시 자동 해금 | 별 2와 별 4에서 기술 1개씩 | 유닛당 2개 |

- 조각은 스테이지 클리어 보상과 별 달성 보상으로 얻습니다. 스테이지마다 주는 조각이 달라서, 키우고 싶은 유닛에 맞춰 다시 도전할 이유가 생깁니다.
- 고유 기술 예시: 블레이드봇은 세 번째 공격마다 2배 피해, 슈터봇은 첫 레이저가 관통, 실드봇은 주변 아군이 받는 피해 20% 감소, 플라즈마봇은 맞은 적 이동 속도 감소, 대시봇은 첫 돌격 피해 3배.
- 덱 편성: 보유 유닛 중 5종을 골라 슬롯 그림으로 올립니다. 1차 출시의 8종 중에서도 상대 스테이지에 맞춰 덱을 바꾸는 재미가 있고, 업데이트로 유닛이 늘수록 수집과 덱 구성의 폭이 넓어집니다.
- 판 안의 단계(1~3단계, 슬롯 조합)와 판 밖의 레벨·별은 별개입니다. 전투 능력치는 두 배율을 곱해 정합니다.
- 화폐는 골드(플레이로 획득)와 보석(나중에 유료 판매) 두 가지를 처음부터 둡니다. 1차에서는 보석을 별 보상으로만 줍니다.

**규칙 세부 해석(M1에서 확정)**

설계에서 수치나 처리 방식이 정해지지 않았던 부분을 M1 구현에서 아래와 같이 정했습니다. 수치는 `battle.json`에 있습니다.

| 항목 | 정한 내용 |
| --- | --- |
| 근접 사거리 | 0.8 |
| 유닛 충돌 | 유닛끼리 막거나 밀지 않고 서로 통과합니다. 사거리 안에 공격할 수 있는 적이 있으면 멈춰서 공격합니다 |
| 공격 처리 순서 | 같은 틱의 공격은 동시에 처리합니다. 먼저 나온 유닛이 유리하지 않습니다 |
| 성의 공격 | 성은 공격하지 않습니다 |
| 배치 위치 | 라인과 라인 위의 거리(내 성에서 0~10) 하나로 정합니다. 라인 안의 좌우 위치는 없습니다 |
| 적 소환 위치 | 적 성 앞 1.0 지점(시간표에서 바꿀 수 있음) |
| 스웜봇의 단계 | 단계가 올라도 3기 그대로이고, 기당 체력과 공격력에 단계 배율을 곱합니다. 3기는 뒤쪽으로 0.3 간격으로 늘어섭니다 |
| 붐봇 | 사거리 안에 적이나 성이 닿으면 자기 위치 반경 1.5에 폭발합니다. 폭발 피해는 공격력이라 단계 배율이 적용되고, 공중 유닛에게는 닿지 않습니다 |
| 플라즈마봇 | 맞은 지점 반경 1.0 안의 지상 적에게 같은 피해를 줍니다 |
| EMP 폭격 | 지정한 라인 안에서 반경 2.0 안의 적에게만 맞고, 공중 유닛에게도 맞습니다. 전장 어디든 조준할 수 있습니다. 기절한 적은 이동과 공격을 모두 멈춥니다 |
| 무승부 | 3분 종료 시 성 체력 비율이 같거나, 두 성이 같은 틱에 무너지면 무승부입니다 |
| 진행 간격 | 초당 20틱은 구조 규칙이라 JSON이 아니라 코드 상수로 둡니다 |

## 4. 기술 스택과 아키텍처

Unity(C#)로 만들되, 게임 규칙은 Unity와 무관한 순수 C# 라이브러리로 분리합니다. Claude Code가 Unity 에디터 없이도 규칙을 테스트할 수 있게 하기 위해서입니다.

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 엔진 | Unity 6 LTS, 2D(URP) | C# 경험 활용, iOS·Android 동시 빌드, 광고·결제 SDK가 가장 잘 갖춰짐 |
| 언어 | C# | |
| 데이터 | JSON 파일 | 코드 수정 없이 밸런스 조정 |
| 저장 | 기기 내 JSON 파일 | 1차는 서버 없음 |
| 테스트 | NUnit, `dotnet test` | Unity 없이 실행 가능 |
| 그림 | 1차 개발 중에는 색깔 도형 | 재미 검증 후 실제 그림으로 교체 |

**계층 구조**

- **Core**: 게임 규칙 전부(슬롯, 소환, 배치, 전투, 승패, 강화 카드, 육성 계산). `UnityEngine`을 참조하지 않습니다.
- **Presentation**: Core의 상태를 화면에 그리고 터치 입력을 Core에 전달합니다. 규칙 판단을 하지 않습니다.
- **Services**: 저장, 광고, 결제, 분석. 모두 인터페이스로 정의하고 1차에는 가짜 구현을 둡니다.
- **Data**: 유닛, 슬롯, 카드, 스테이지, 육성 비용 JSON.

**Core 설계 규칙**

- 고정 간격(초당 20회)으로 진행하는 시뮬레이션입니다. `BattleSimulation.Tick()`을 호출할 때마다 한 단계 진행합니다.
- 난수는 시드를 받는 자체 생성기 하나만 씁니다. 같은 시드와 같은 입력이면 결과가 항상 같아야 합니다.
- 플레이어 입력은 명령 객체(스핀, 고정 후 다시 돌리기, 결과 확정, 유닛 배치(라인과 위치), 사령관 기술 사용(위치), 카드 선택)로만 받습니다.
- 이 세 가지를 지키면 자동 밸런스 시뮬레이션, 리플레이, 나중의 비동기 대전을 추가 설계 없이 붙일 수 있습니다.

**폴더 구조**

```
SlotBattle/
  CLAUDE.md                  # Claude Code 작업 지침 (7장)
  docs/DESIGN.md             # 이 설계서
  Assets/
    Scripts/
      Core/                  # 순수 C#, UnityEngine 참조 금지
        Battle/              # BattleSimulation, Unit, Castle, Lane
        Slot/                # SlotMachine, SpinResult, SummonRule
        Cards/               # UpgradeCard, CardPool
        Growth/              # UnitProgress, LevelUp, StarUp, Deck
        Economy/             # Wallet(골드, 보석), Reward
        Data/                # JSON에 대응하는 정의 클래스
        Util/                # SeededRandom
      Presentation/          # MonoBehaviour: 전투 화면, 슬롯 UI, 메뉴, 육성 화면
      Services/              # ISaveService, IAdService, IIapService, IAnalytics
    Data/                    # units.json, slot.json, battle.json, cards.json, stages.json, growth.json, feel.json
    Scenes/Bootstrap.unity   # 유일한 씬, 나머지는 코드로 생성
  Tests/
    Core.Tests/              # Core 소스를 직접 포함하는 별도 .csproj
  Tools/
    BalanceSim/              # 콘솔 앱: 자동 플레이 1,000판 후 승률 출력
```

씬과 프리팹을 에디터에서 손으로 만들지 않고, 화면 요소를 코드로 생성합니다. Claude Code가 텍스트 파일만으로 전체를 다룰 수 있게 하기 위해서입니다.

## 5. 개발 단계

여섯 단계로 나누고, 한 단계의 완료 기준을 통과한 뒤에만 다음 단계를 Claude Code에 요청합니다. M2가 재미를 판단하는 지점입니다.

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| M0 뼈대 | 폴더 구조, Core 프로젝트, 테스트 프로젝트, CLAUDE.md, JSON 초기 데이터 | `dotnet test`가 빈 테스트 1개로 통과 |
| M1 전투 규칙 | SeededRandom, 슬롯과 소환 규칙, 대기 칸과 배치, 유닛 이동·공격, 유닛 특성 키워드, 사령관 기술, 성, 승패, 적 시간표, BalanceSim | 2장의 규칙마다 테스트 존재, 같은 시드로 두 번 돌린 결과 동일, BalanceSim이 스테이지 1 승률 출력, 숙련형 자동 플레이어 승률이 초보형보다 25%포인트 이상 높음 |
| M2 플레이 가능한 한 판 | Unity 화면 연결: 라인, 유닛(도형), 체력 막대, 슬롯 UI, 고정 후 다시 돌리기, 대기 칸과 끌어다 놓기, 결과 화면, 8장의 M2 연출 | 폰에서 스테이지 1을 처음부터 끝까지 플레이 가능. **여기서 재미를 직접 판단하고, 부족하면 규칙부터 고칩니다** |
| M3 콘텐츠 | 강화 카드 12장, 스테이지 10개, 별 평가 | BalanceSim 기준 스테이지 1 승률 90% 이상, 스테이지 10은 육성 없이 20% 이하 |
| M4 육성과 저장 | 레벨업, 승급, 고유 기술, 덱 편성, 골드·보석·조각, 저장, 메인 메뉴·스테이지 선택·육성 화면 | 앱을 껐다 켜도 진행 상황 유지, 육성 계산에 테스트 존재, 육성 후 스테이지 10 승률 상승 확인 |
| M5 출시 준비 | 실제 그림과 효과음, 8장의 M5 연출, 튜토리얼, 보상형 광고 실제 연결, 스토어 빌드 | Android 내부 테스트 배포, 지인 5명 이상 플레이 후 의견 수집 |

**출시 이후 업그레이드 순서**

1. 유닛 추가(업데이트 1에 4종, 업데이트 2에 3종, 총 15종), 스테이지 확장, 일일 도전
2. 상점과 결제(6장)
3. 다른 유저의 덱·육성 상태와 싸우는 비동기 대전, 이때 서버와 로그인 도입
4. 시즌 패스와 랭킹

## 6. 유료화 설계

1차는 보상형 광고만 넣고, 결제는 유닛 육성을 중심으로 나중에 붙입니다. 육성 재료(골드, 조각)가 공급과 소비의 중심이라 여기에 상품을 걸기 쉽습니다.

| 시점 | 수익 수단 | 내용 |
| --- | --- | --- |
| 1차 출시 | 보상형 광고 | 승리 보상 2배, 패배 시 성 체력 50%로 1회 부활, 하루 3회 조각 보너스 |
| 업그레이드 2 | 일회성 구매 | 광고 제거(보상은 광고 없이 지급), 스타터 팩 |
| 업그레이드 2 | 보석 판매 | 보석으로 골드·조각 묶음과 유닛 외형을 구매. 내용물이 확정된 상품만 판매 |
| 업그레이드 4 | 시즌 패스 | 한 달 단위 무료·유료 보상 트랙 |

**1차부터 코드에 넣어둘 것**

- `Wallet`에 골드와 보석 두 화폐, 유닛별 조각 수량
- `IAdService`, `IIapService` 인터페이스와 가짜 구현
- 보상 지급을 한 곳(`RewardService`)으로 모으기. 광고 보상과 구매 보상이 같은 경로를 씁니다.
- `IAnalytics`로 스테이지 시작·종료, 스핀 횟수, 이탈 지점 기록

**지킬 원칙**

- 슬롯은 게임 안 마나로만 돌립니다. 현금이나 보석으로 돌리는 슬롯은 만들지 않습니다.
- 유료 랜덤 상자는 넣지 않습니다. 넣게 되면 확률 공개 등 국내 규정을 먼저 확인합니다.
- 결제하지 않아도 모든 스테이지를 깨고 모든 유닛을 별 5개까지 키울 수 있어야 합니다. 결제는 시간을 줄여주는 역할만 합니다.

## 7. Claude Code 작업 지침과 첫 요청문

이 설계서를 저장소의 `docs/DESIGN.md`에 넣고, 작업 지침을 `CLAUDE.md`로 저장한 뒤 첫 요청문을 보내면 됩니다. 작업 지침의 내용은 저장소 최상위의 `CLAUDE.md` 파일을 따릅니다.

**첫 요청문**

```
docs/DESIGN.md와 CLAUDE.md를 읽고 M0(뼈대)와 M1(전투 규칙)을 구현해 줘.

- Unity 프로젝트 폴더 구조를 만들되, 이번에는 Core와 테스트, BalanceSim만 작성해.
  Presentation은 만들지 마.
- 3장의 초기 수치로 units.json(1차 출시 8종), slot.json, stages.json(스테이지 1~3)을 만들어.
- 2장의 규칙 하나하나에 대응하는 테스트를 써.
- BalanceSim은 아무 라인에나 즉시 놓는 초보형과, 상성과 대형을 따져 배치하는 숙련형
  두 자동 플레이어로 스테이지별 1,000판씩 돌려 승률과 평균 판 길이를 출력해.
- 끝나면 완료 기준별 충족 여부와, 설계서에서 모호했던 부분을 어떻게 해석했는지 알려줘.
```

**이후 요청 요령**

- 한 번에 한 단계만 요청하고, 완료 기준을 직접 확인한 뒤 다음으로 넘어갑니다.
- M2부터는 Unity 에디터에서 직접 실행해 보고, 느낀 점을 구체적으로 적어 수정을 요청합니다(예: "스핀이 너무 자주 돌아가서 정신없다. 비용을 4로 올리고 승률을 다시 봐줘").
- 규칙이나 수치를 바꾸기로 하면 이 설계서부터 고치고 코드를 맞춥니다.

## 8. 재미 요소와 연출

이 게임의 재미는 규칙보다 "누를 때와 맞출 때의 손맛"에서 더 많이 나옵니다. 그래서 연출을 나중에 얹는 장식이 아니라 완료 기준에 들어가는 기능으로 다룹니다.

**사용자가 재미를 느끼는 지점과 구현 방법**

| 재미 요소 | 왜 재미있나 | 구현 | 단계 |
| --- | --- | --- | --- |
| 슬롯의 기대감 | 결과를 기다리는 짧은 긴장이 핵심 쾌감 | 세 칸이 왼쪽부터 0.25초 간격으로 차례로 멈춤. 앞 두 칸이 같으면 세 번째 칸은 0.6초 더 느리게 돌다 멈춤 | M2 |
| 슬롯 움직임 | 묵직하게 돌고 딱 멈추는 감각 | 빠르게 가속, 멈출 때 살짝 지나쳤다 되돌아오는 반동, 도는 동안 그림 흐림 처리 | M2 |
| 버튼 반응 | 누른 즉시 반응해야 내가 한 것처럼 느낌 | 누르는 순간 버튼이 눌리고 0.1초 안에 릴이 돌기 시작. 스핀 전체는 1초 이내 | M2 |
| 잭팟 | 드문 큰 보상이 다시 돌리고 싶게 만듦 | 세 칸이 같으면 0.3초 멈춤, 화면 번쩍임, 3단계 유닛이 크게 떨어지며 착지 충격파 | M2 |
| 타격감 | 때리는 무게가 느껴져야 전투를 계속 보게 됨 | 맞은 유닛이 흰색으로 번쩍이고 뒤로 살짝 밀림, 피해 숫자가 튀어 오름, 타격 순간 0.03~0.05초 멈춤 | M2 |
| 큰 한 방 | 강한 유닛과 약한 유닛의 차이가 눈에 보여야 함 | 3단계 유닛의 공격과 성 타격에만 화면 흔들림, 유닛 단계가 높을수록 크기와 빛 효과 증가 | M2 |
| 처치 쾌감 | 적이 터져 나가는 것이 작은 보상 | 죽을 때 터지는 조각 효과, 성이 무너질 때 느린 화면과 큰 폭발 | M2 |
| 소리 | 손맛의 절반은 소리 | 릴이 멈출 때마다 "딸깍" 소리, 같은 그림이 이어지면 음이 한 단계씩 높아짐, 타격음은 매번 높낮이를 조금씩 다르게 재생 | M5 |
| 진동 | 손에 전해지는 반응 | 릴 정지는 약한 진동, 잭팟과 성 파괴는 강한 진동. 설정에서 끄기 가능 | M5 |
| 역전의 긴장 | 끝까지 결과를 모르는 판이 기억에 남음 | 마지막 30초는 마나 회복 2배, 배경음 빨라짐, 남은 시간 강조 표시 | M3 |
| 성장의 체감 | 키운 결과가 눈에 보여야 키울 맛이 남 | 레벨업 시 수치가 이전 값에서 새 값으로 올라가는 연출, 승급 시 외형 변화와 전용 연출 | M4 |
| 보상 연출 | 받는 순간을 길게 느끼게 함 | 승리 시 별이 하나씩 찍히고, 골드와 조각이 지갑으로 날아들며 숫자가 올라감 | M4 |

**UI/UX 손맛 세부 규칙**

화면의 모든 조작은 "누르면 즉시, 눈과 귀와 손으로 동시에" 반응해야 합니다.

| 조작 | 감각 요소 | 단계 |
| --- | --- | --- |
| 한 손 조작 | 슬롯과 버튼을 화면 아래 3분의 1, 엄지가 닿는 영역에 배치. 버튼은 손가락보다 크게(최소 48dp) | M2 |
| 모든 버튼 | 누르는 순간 92% 크기로 줄었다가 탄성 있게 되돌아옴. 반응 지연 없음 | M2 |
| 스핀 버튼 | 마나가 충분해지면 맥박처럼 천천히 커졌다 작아지며 누르라고 알림. 부족할 때 누르면 좌우로 짧게 떨리고 부족한 마나 칸이 빨간색으로 깜빡임 | M2 |
| 길게 누르기 | 스핀 버튼을 누르고 있으면 마나가 찰 때마다 자동으로 돌고 결과를 대기 칸으로 확정 | M3 |
| 칸 고정 | 고정할 칸을 직접 터치. 자물쇠가 "철컥" 잠기는 애니메이션과 소리, 고정된 칸은 테두리가 빛남 | M2 |
| 마나 게이지 | 칸 단위로 부드럽게 차오르고, 한 칸이 찰 때마다 짧게 반짝임. 쓸 때는 쓴 만큼이 한 번에 빠지며 퍼지는 효과 | M2 |
| 유닛 소환 | 슬롯 그림이 칸에서 튀어나와 대기 칸으로 날아감. 대기 칸의 유닛을 잡으면 살짝 커지며 손가락을 따라오고, 놓을 수 있는 영역과 사거리가 표시됨. 놓는 순간 착지 충격과 진동 | M2 |
| 강화 카드 | 카드 3장이 차례로 뒤집히며 등장. 고른 카드는 커지며 빛나고 나머지는 사라짐 | M3 |
| 숫자 변화 | 골드, 성 체력, 능력치는 바로 바뀌지 않고 빠르게 세어 올라가거나 내려감 | M2 |
| 성 체력 막대 | 피해를 입으면 줄어든 부분이 흰색으로 남았다가 뒤늦게 따라 줄어듦 | M2 |
| 화면 전환 | 0.2초 이내. 패배 후 한 번의 터치로 바로 다시 시작 | M4 |
| 레벨업 버튼 | 강화할 수 있는 유닛에 표시 점. 누르고 있으면 연속으로 올라가며 소리의 음이 점점 높아짐 | M4 |

- 화면은 초당 60장을 유지합니다. 끊기면 어떤 연출도 손맛이 나지 않습니다.
- 연출이 조작을 막지 않게 합니다. 잭팟 연출 중에도 다음 스핀을 누를 수 있고, 보상 연출은 터치로 건너뛸 수 있습니다.

**구현 원칙**

- Core는 사건만 알립니다(릴 정지, 잭팟, 유닛 소환, 타격, 사망, 성 피해). 연출은 Presentation이 이 사건을 받아 재생합니다.
- 타격 순간의 멈춤과 느린 화면은 화면 표시에만 적용하고 Core의 진행 시간은 바꾸지 않습니다.
- 연출 수치(시간, 흔들림 세기, 밀리는 거리)는 `feel.json`에 두어 코드 수정 없이 조정합니다.
- 슬롯 연출은 결과를 속이지 않습니다. 결과는 Core가 먼저 정하고, 세 번째 칸을 느리게 돌리는 연출은 앞 두 칸이 실제로 같을 때만 씁니다.
- 화면 흔들림과 진동은 설정에서 끌 수 있게 합니다.

**재미 판단 기준(M2에서 직접 확인)**

- [ ] 아무 설명 없이도 슬롯 버튼을 또 누르고 싶은가
- [ ] 같은 그림 두 개가 나왔을 때 세 번째 칸을 지켜보게 되는가
- [ ] 3단계 유닛이 나왔을 때 확실히 강하다고 느껴지는가
- [ ] 어디에 놓을지 고민하게 되고, 잘 놓았을 때 이겼다고 느껴지는가
- [ ] 지고 나서 한 판 더 하고 싶은가

## 9. 결정이 필요한 사항과 위험 요소

개발을 시작하는 데는 아래 결정이 필요 없고, M5 전까지만 정하면 됩니다.

**결정할 것**

- [ ] 게임 이름(세계관은 AI 로봇 전투로 확정). 기존 게임과 겹치지 않는 이름인지 스토어에서 검색해 확인
- [ ] 그림 준비 방법: 에셋 스토어 구매, 외주, 직접 제작 중 선택. 구매한 에셋은 상업적 이용 조건 확인
- [ ] 효과음과 배경음 출처
- [ ] 출시 순서: Android 먼저 테스트하고 iOS는 그다음(권장)
- [ ] 한 판의 길이 (M2 전에 결정): M1 BalanceSim에서 한 판이 평균 35~60초 만에 끝나 목표인 3분보다 훨씬 짧습니다. 성 체력 1,000에 비해 플레이어의 소환 속도가 빠르기 때문입니다. 성 체력, 스핀 비용, 마나 회복 속도 중 무엇을 조정할지 정합니다

**배포에 필요한 것**

- iOS: 빌드와 제출에 Mac과 Xcode, Apple 개발자 프로그램 가입(연 99달러). Mac이 없으면 클라우드 빌드 서비스를 씁니다.
- Android: Google Play 개발자 계정(가입비 25달러, 1회). 신규 개인 계정은 정식 출시 전에 비공개 테스트 요건이 있으니 가입할 때 최신 조건을 확인합니다.
- 국내 출시: 스토어의 연령 등급 설문을 거칩니다. 슬롯 연출이 있으므로 도박 모사 항목에 어떻게 답할지 미리 확인합니다.

**위험 요소와 대응**

| 위험 | 대응 |
| --- | --- |
| 핵심 플레이가 재미없음 | M2에서 멈추고 규칙을 고칩니다. 그림과 콘텐츠에 시간을 쓰기 전에 판단합니다 |
| 운에만 좌우되어 선택의 의미가 없음 | 배치, 고정 후 다시 돌리기, 강화 카드, 덱 편성으로 선택지를 늘립니다. BalanceSim에서 초보형과 숙련형 자동 플레이어의 승률 차이를 확인합니다 |
| 조작이 많아 한 판이 너무 바쁨 | 대기 칸 크기, 스핀 비용, 마나 회복 속도를 M2에서 직접 해보며 조정합니다 |
| 육성이 지루한 반복이 됨 | 스테이지당 필요한 반복 횟수를 BalanceSim으로 계산해, 다음 스테이지까지 3~5판 안에 도달하도록 비용을 잡습니다 |
| 기존 게임과 닮았다는 문제 제기 | 이름·그림·화면 구성·수치를 직접 만들고, 출시 전에 특정 게임과 나란히 놓고 비교합니다. 애매하면 게임 전문 변호사에게 확인받습니다 |
| Unity 화면 작업을 Claude Code가 직접 확인하지 못함 | 규칙은 Core 테스트로 검증하고, 화면은 에디터에서 직접 확인해 화면 사진과 함께 수정을 요청합니다 |
